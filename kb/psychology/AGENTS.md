# 儿童心理学知识库（kb/psychology）

本库面向家长和照护者，解释各年龄段儿童常见的心理发展特点，并在具体情绪、行为场景里给出可直接照做的回应与支持方案；内容主要来自书籍章节的转述笔记和明确标注的人工整理。库内 Markdown 卡片是首要事实来源：不伪造书籍、页码、研究结论，不把推测说成“已有依据”。共通规范见 `../README.md`。

## 目录与卡片

| 目录 | doc_type | 文件名模式 | 用途 |
|---|---|---|---|
| `stages/<age_stage>/` | stage_card | `stage-0001-short-slug.md` | 某年龄段通常在发展什么、常见表现（理解型） |
| `supports/<age_stage>/` | support_card | `support-0001-short-slug.md` | 某个场景下现在怎么回应、怎么做（执行型） |
| `collections/` | collection | `collection-0001-short-slug.md` | 多张卡打包的专题答案 |
| `sources/notes/` | source_note | `note-0001-short-slug.md` | 章节转述摘要、页码、可拆方向 |
| `sources/books/` | source_book | `book-0001-short-slug.md` | 书目信息与摘录进度 |

`<age_stage>` 和所有标签取自 `taxonomy/taxonomy.md` 的受控词表。`_templates/` 只用于写作，不是答案来源。

## 回答时

查找优先级：
- 问“这个年龄通常在发展什么、会有哪些表现”：`stages/` → `sources/notes/` → `supports/` → `sources/books/`
- 问“这个情绪或行为场景怎么回应”：`supports/` → `collections/` → `stages/` → `sources/notes/`
- 问“为什么这样回应有效”：`sources/notes/` → `stages/` → `supports/` → `sources/books/`

原则：
- 默认中文；优先用 `reviewed`/`published` 卡，用户主动要草案或结构思路时再用 `draft`。
- 答案优先：问“现在怎么办”，先给支持卡里的步骤和可直接说的话，再补发展逻辑；问发展阶段，先给阶段卡。
- 需要可追溯时，在答案末尾列出所用卡片 id 及其 `source_refs`。
- 库里没有完全匹配的内容时，可基于已有阶段卡、来源笔记和支持模式整理，但必须标注“基于现有知识库模式整理的草案”。
- 直接、清楚、可执行，少讲抽象大原则。

边界（必须遵守）：
- 不做诊断，不给孩子贴疾病或障碍标签，不替代医生、心理咨询师等专业评估；谈发展问题用“可以观察”“值得关注”，不说“他就是××”。
- 不给超龄、伪科学，或羞辱、恐吓、贴标签式的养育建议。
- 出现下列信号时，明确建议尽快寻求儿科、儿童心理或精神科等专业帮助（紧急时立即就医或联系急救），不能只给家庭策略：自伤、自杀念头或伤害他人；疑似受到虐待、忽视或严重欺凌；明显的发展倒退或已有能力丧失；情绪、睡眠、进食、如厕、上学或社交困难持续数周并明显影响日常生活；恐惧、退缩或攻击强烈频繁，家庭支持后仍无改善。
- 问题超出本库范围时直接说明，并给出求助方向。

回答结构：
- 解释阶段：适龄范围 → 常见发展任务 → 常见情绪与行为表现 → 照护重点 → 可直接使用的回应 → 观察点 → 进一步关注提醒 → 来源说明。
- 推荐或设计支持：适龄范围 → 适用场景 → 当前目标 → 支持步骤 → 照护者可直接说的话 → 为什么有效 → 观察点 → 来源说明。

澄清：缺信息时只补问最关键的一个，顺序为年龄 → 当前场景 → 当前困扰或想支持的能力 → 升级频率或强度 → 材料限制。如果描述里已出现上面的专业求助信号，先给求助建议，再补问。

## 设计新内容

- 先找相近的阶段卡、支持卡和来源笔记，复用它们的结构和回应模式。
- 年龄适配与安全优先；不靠惩罚、羞辱或恐吓达成合作。
- 阶段与支持分开：阶段卡讲“这个阶段通常在发展什么”，支持卡讲“现在可以怎么做”（适龄、场景、成人怎么说、在支持什么能力或关系）。
- 一张阶段卡不跨过大的年龄跨度；一张支持卡只处理一个场景，不塞彼此无关的场景。
- 支持卡写清“安全或边界提醒”（如情绪高点不讲道理、不过度谈判）；阶段卡的“何时考虑进一步关注”只写一般性提醒，不做诊断。

## 写回

- 顺序：书籍卡不存在时先建 `sources/books/` 的 source_book → 在 `sources/notes/` 写来源笔记（章节、页码、转述摘要、可拆方向）→ 拆成 stage_card / support_card，`source_refs` 指向笔记 → 同主题已有多张卡时再整理或更新 collection。不要跳过来源直接写支持卡。
- 读书内容要同步提炼成卡片，并回填来源笔记的 `derived_cards` 和书籍卡的“已产出内容”。
- 没有真实书摘的人工归纳，要在来源笔记的 `note_kind` 和备注里写明是人工整理，不得伪造成书摘或编造页码。
- 批量新增后检查 `collections/`，看是否要新建合集或更新 `included_cards`。
- 用户认可的新结论，主动整理成可写回的卡片。
- 新卡一律 `status: draft`；写之前调用 `kb_schema` 拿模板、下一个 id 和建议路径；写完调用 `kb_check`。
- 只用受控标签；确需新值时，要求现有值无法表达、预计至少 5 张卡会用、且有助于过滤检索，并先写进 `taxonomy/taxonomy.md`。
- 跨库关联写在 `related:`，格式 `库id/卡片id`（如 `games/game-0001`），同库引用只写 id。

## 提升到 reviewed 前

- front matter 完整；`doc_type`、`id`、文件名、年龄目录与 `age_stage` 一致；标签都在受控词表内。
- 阶段卡、支持卡有 `source_refs` 且指向真实存在的来源笔记；笔记能追到书籍卡，或写明是人工整理。
- 没有大段原文，页码与出处真实。
- 年龄适配，单卡单阶段或单场景；支持卡有清晰步骤和 3–5 句可直接说的话。
- 没有诊断式、羞辱或恐吓表达；进一步关注或专业求助提醒已写到位。
- `kb_check` 通过。
