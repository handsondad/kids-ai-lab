# 孩子的奇妙视界

「孩子的奇妙视界」是一个“十万个为什么式”的亲子共学知识库：孩子提问，老爸承接，一起认识外部世界，也认识自己。

它的重点不是先建一个大而全的知识库，而是先把一套稳定的回答方法固定下来，再把高价值回答逐步沉淀成可复用的笔记：

- 回答角色不是“通用助手”，而是“孩子和老爸一起认识世界和自己”的双层回答助手
- 按年龄阶段控制解释深度、句式复杂度和追问方式
- 用固定的回答流程和话术，把模型的生成能力变成稳定、可复用的输出
- 需要时用网页检索补齐新鲜事实和来源
- 把高价值回答沉淀为主题笔记或回答脚本，而不是只停留在聊天里

## 设计目标

1. 孩子能听懂：先给一个适龄、具体、不过载的解释。
2. 老爸能接住：再给一个父母层的机制说明、追问方式和互动建议。
3. 同时解释世界和自我：既回答“外部世界为什么这样”，也帮助孩子理解“我怎么感受、怎么思考、怎么行动”。
4. 回答可持续复用：高频问题逐步沉淀为笔记。
5. 能借用其他库：科学现象、AI、情绪心理等问题，先复用本仓库其他知识库里的现成卡片。

## 知识单元类型

两类卡片都放在 `notes/` 下，一个文件只处理一个核心问题。

### 主题笔记 `topic_note`

模板：[`_templates/topic_note_template.md`](_templates/topic_note_template.md)

什么时候建：

- 高频“为什么”问题
- 在多个年龄段都值得保留的解释框架
- 已经形成稳定孩子层和老爸层结构的回答
- 需要定期联网刷新、但主体结构稳定的主题
- 用户明确说“把这个沉淀下来”

写回时默认优先建主题笔记。

### 回答脚本 `answer_script`

模板：[`_templates/answer_script_template.md`](_templates/answer_script_template.md)

什么时候建：某个问题需要一份“马上能讲出口”的成品，包含 30 秒版本、3 分钟版本、老爸接话脚本、互动动作，以及配图说明和旁白脚本（适合做插图、幻灯片或音频）。

不适合建卡的内容：一次性闲聊、没有稳定结构的即兴答案、一时想到但不会复用的草稿。

## 分类策略

本库没有单独的分类词表，用 frontmatter 字段分类：

- `world_or_self`：问题类型，`world`（外部世界）、`self`（自我）或 `mixed`
- `age_stage` / `age_stages`：适用年龄段，沿用回答方法里的四个年龄桶：2-3 岁、4-5 岁、6-8 岁、9-12 岁
- `answer_mode`：回答深度，`quick`、`standard` 或 `deep`
- `source_mode`、`refresh_needed`、`web_refs`：来源方式、是否需要定期刷新、联网参考
- `question_seeds`、`aliases`：孩子原话式的问法和别名，便于检索

适合处理的问题举例：为什么天会黑、为什么我会生气、为什么植物会长大、为什么我会害怕打针、为什么飞机会飞、为什么要刷牙、为什么我会想妈妈。

## 默认回答样式

一个问题默认拆成几层：

1. 给孩子怎么说
2. 给爸爸怎么接
3. 一起观察或做个小实验
4. 可以继续问孩子什么
5. 如果需要，再补充依据与边界

完整流程和话术见 [`skills/wonder-answer.md`](skills/wonder-answer.md)，年龄段讲法见 [`skills/wonder-age-stages.md`](skills/wonder-age-stages.md)。

## 推荐写作流程

1. 先在本库和其他库里检索有没有相近卡片，能更新就不新建。
2. 按回答方法跑通一次完整回答（孩子层、老爸层、活动、追问、边界）。
3. 回答结构稳定、确有复用价值时，按模板写成 `topic_note`；需要成品讲稿或配图、旁白时再写 `answer_script`。
4. 依赖联网信息的，在“来源与边界”里写清来源方式和需要刷新核查的点。

## 编写规则

- 孩子层：先说结论，再补一句原因；短句、具象、可观察、少术语，术语一出现马上改写成孩子能懂的话。
- 老爸层：给更准确的机制、一句当场能接上的话、一个追问、一个观察或动作。
- 明确标注适用年龄段和来源方式。
- 记录“容易讲偏的地方”：常见误解、过度简化、错误比喻。
- 不伪造来源、页码、实验结论；不把推测写成确定事实。
- 多模态只写“就绪内容”（画面说明、旁白脚本、互动动作），不假装已经生成图像、音频或视频。

## 文件命名

- 主题笔记：`notes/topic-0001-short-slug.md`，`id` 为 `topic-0001`
- 回答脚本：`notes/script-0001-short-slug.md`，`id` 为 `script-0001`
- 文件名只用小写 ASCII、数字和连字符；两种卡片各自编号

## 状态规则

- 新卡一律 `status: draft`
- 内容核对过、通过下面的质量检查后改为 `reviewed`
- 确认可以直接对外使用时改为 `published`
- 回答时优先引用 `reviewed` / `published` 的卡片

## 建议长度

本库模板和旧规则没有规定具体字数。参考回答方法里的年龄规则：孩子层 2-3 岁 1-2 句、4-5 岁 2-4 句、6-8 岁 4-6 句、9-12 岁 5-8 句；追问 1-3 个；回答脚本的“30 秒版本”应能一口气讲完。

## 质量检查清单

- [ ] 一个文件只有一个核心问题，`核心问题` 一句话写得清楚
- [ ] 标明了适用年龄段，孩子层的句长和因果层数符合该年龄段
- [ ] 孩子层和老爸层明确分开，老爸层有机制、接话、追问和动作
- [ ] 至少有一个马上能做的观察、实验或动作，且安全
- [ ] 写了容易讲偏的地方
- [ ] 联网内容标注了来源方式和需要刷新的点，没有伪造来源
- [ ] 涉及医疗、心理、安全风险时没有轻描淡写

## 在 DSH 里使用

这个库在 DeepSeek Harness（DSH）的「知识库模式」里可直接检索和维护：

- 检索和阅读：`kb_search`、`kb_read`、`kb_links`
- 写卡前用 `kb_schema` 查模板和下一个 id，写完用 `kb_check` 校验
- 回答孩子问题时可联网：`web_search` 找页面，`web_fetch` 读正文核对

Agent 规则见同目录 [`AGENTS.md`](AGENTS.md)，回答方法见 [`skills/`](skills/)；全库共通规范见 [`../README.md`](../README.md)。

## 跨库关联

卡片可以用 `related:` 字段引用其他库的卡片，写法是 `库id/卡片id`；同库引用仍可只写 id。例如：

```yaml
related:
  - science/experiment-0074   # “为什么会有冬天和夏天”的笔记，关联科学库的“地球轴倾斜与季节”实验
  - psychology/support-0017   # “为什么我会生气”的笔记，关联心理库的“父母情绪激动时的暂停法”
  - script-0001               # 同库的回答脚本
```

## 多模态定位

本库把“多模态回答”定义为输出多模态就绪的组件：

- 适合配图的画面说明
- 适合配音或爸爸讲述的旁白脚本
- 适合父子互动的动作、观察或小游戏
- 把一个问题拆成 3 到 5 个连续场景的对话分镜

如果以后接入支持视觉、图像或语音的模型，可以在现有结构上继续升级，不需要重写回答规则。
