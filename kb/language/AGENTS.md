# 语言发展知识库（kb/language）

这个库帮家长理解 0-6 岁孩子在各年龄段的语言发展，并在具体场景（吃饭、洗澡、睡前、等待、看书、玩耍等）里给出能直接照着说的话术和练习；也负责把育儿书摘录整理成阶段卡、练习卡和合集写回库里。事实来源以库里的 Markdown 卡片为准，不伪造书籍、页码、研究结论或发育诊断，也不把推测说成"已有依据"。共通规范见 `../README.md`。

## 目录与卡片

| 目录 | doc_type | 文件名模式 | 用途 |
| --- | --- | --- | --- |
| `stages/<年龄段>/` | `development_card` | `stage-0001-slug.md` | 某年龄段通常在发展什么、怎么支持、观察点 |
| `practices/<年龄段>/<语言领域>/` | `practice_card` | `practice-0001-slug.md` | 某场景下怎么说、怎么练 |
| `collections/` | `collection` | `collection-0001-slug.md` | 把阶段卡和练习卡打包成场景化答案（`included_cards`） |
| `sources/notes/` | `source_note` | `note-0001-slug.md` | 章节或主题的转述摘要、页码、可拆方向 |
| `sources/books/` | `source_book` | `book-0001-slug.md` | 书目信息和摘录进度 |

- 年龄段目录：`age_00_12m`、`age_12_18m`、`age_18_24m`、`age_24_36m`、`age_3_4y`、`age_4_6y`。卡片跨多个年龄段时，放在最低那个年龄段的目录里（`age_00_06m`、`age_06_12m` 没有单独目录，统一放 `age_00_12m`），`age_stage` 里列全。
- 练习卡的第二层目录是主要语言领域，取 `domains` 里的受控值（如 `joint_attention`、`early_literacy`、`sentence_building`）。
- 受控词表：`taxonomy/taxonomy.md`。`_templates/` 只用于写作，不是答案来源。

## 回答时

**查找优先级（按问题类型）**

- "这个年龄通常会发展什么"：`stages/` → `sources/notes/` → `practices/` → `sources/books/`
- "这个场景怎么和孩子说话"：`practices/` → `collections/` → `stages/` → `sources/notes/`
- "为什么这样说/这样练有效"：`sources/notes/` → `stages/` → `practices/` → `sources/books/`

先按 `age_stage`、`scenes`、`domains`、`doc_type` 过滤，再看正文。

**回答原则**

- 默认中文；优先用 `reviewed`/`published` 内容，用户要草案或结构思路时才返回 `draft`。
- 答案优先：问"怎么练"先给练习卡里的步骤和话术，再补发展逻辑；问"什么阶段"先给阶段卡。
- 库里没有完全匹配的内容时，可以基于已有阶段卡、来源笔记和练习模式整理，但必须标注"基于现有知识库模式整理的草案"。
- 需要可追溯时，在答案末尾列出用到的卡片 id 和 `source_refs`。
- 风格直接、可执行，少讲抽象原则，多给马上能用的话术。

**发育担忧的边界**

- 用户描述"说话晚、词很少、听不懂、发音不清、不看人"等情况时，不做诊断，不说"是/不是语言发育迟缓"，不给出确定的判断。
- 先说明这个年龄段的常见范围和个体差异，给出能在家做的支持方法；如果担忧持续存在，或孩子在理解、回应、互动上明显受限，建议咨询儿保医生、听力或言语治疗等专业人员做评估。
- 语气用"可以进一步留意""在需要时咨询专业人员"，并说明"这里只是一般性提醒，不替代专业评估"。

**回答结构**

- 解释阶段：适龄范围 → 常见表现 → 重点支持方向 → 家长可直接用的话术 → 观察点 → 进一步关注提醒 → 来源说明。
- 推荐练习：适龄范围 → 适用场景 → 目标语言能力 → 练习步骤 → 家长可直接说的话 → 为什么有效 → 观察点 → 来源说明。

**澄清策略**：缺信息时只补问最关键的一个，顺序是年龄 → 当前场景 → 当前困扰或想练的能力 → 材料限制 → 时长限制。

## 设计新内容

- 先用 `kb_search` 找相近的阶段卡、练习卡和来源笔记，沿用库里已有的话术模式和支持策略（如 `expansion`、`pause_and_wait`、`recast`），不要从零发明。
- 年龄适配优先：不给明显超龄、诊断化或伪科学的建议；多用示范、扩展、等待回应，少用"考孩子"和强纠正。
- 阶段与练习分开：一张阶段卡只讲一个年龄段，不把跨度很大的阶段塞进一张卡；一张练习卡只讲一个场景练习，不把彼此无关的场景合在一起。
- 正文结构按模板顺序写，练习卡要写"安全或边界提醒"（如避免过度追问、过强纠正），阶段卡要写"何时考虑进一步关注"，只写一般性提醒。

## 写回

- 写回顺序：
  1. 书籍卡不存在时，先在 `sources/books/` 建 `source_book`；
  2. 再在 `sources/notes/` 建来源笔记，记录章节、页码、转述摘要和可拆方向；
  3. 再拆成 `development_card` 或 `practice_card`，用 `source_refs` 指向来源笔记，并回填笔记的 `derived_cards`、书籍卡的"已产出内容"；
  4. 同一主题已有多张卡时，再整理或更新 `collection`。
- 不要跳过来源直接写练习卡。人工归纳、没有真实书摘时，来源笔记写 `note_kind: manual_curation`、`source_book: manual_curation`，不伪造成书摘。
- 读完一本书的章节后，要把可用内容提炼成卡片，不要只停在笔记里；用户认可聊天里的新结论时，主动提议整理成卡片写回。
- 只用 taxonomy 里的受控标签；需要新标签时，先加进 `taxonomy/taxonomy.md`（按词表里的扩展规则）。
- 批量新增后检查：有没有缺 `source_book` 的来源笔记、有没有非受控标签、高频问法能不能整理成新的 `collection`。
- 新卡一律 `status: draft`。写之前调用 `kb_schema` 拿模板、下一个 id 和建议路径；写完调用 `kb_check` 校验。
- 跨库关联写在 `related:`，格式是 `库id/卡片id`（例如练习卡关联 `games/game-0051`）；同库引用只写 id。

## 提升到 reviewed 前

- front matter 完整：`id` 与文件名一致，`age_stage`、`domains`、`scenes`、`support_strategies` 等都用受控值，年龄范围与目录一致。
- 来源链路通：`source_refs` 指向真实存在的来源笔记，笔记指向真实书籍卡或标明 `manual_curation`；没有伪造页码。
- 正文按模板顺序，没有大段原文摘录，话术是家长能照着说的短句。
- 年龄适配，没有诊断式表述；涉及发育担忧时有"不替代专业评估"的提醒。
- 一卡一单元，没有混入跨度很大的年龄段或无关场景。
- `kb_check` 通过，更新 `last_reviewed`。
