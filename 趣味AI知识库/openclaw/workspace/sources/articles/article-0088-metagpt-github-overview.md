# 文章定位

MetaGPT 是多代理协作框架，提出“软件公司角色化协作”范式，将产品、架构、开发等职责映射为可编排代理角色。

## 核心观点

- 以 SOP 驱动的多角色协作作为核心设计理念。
- 可从单条需求生成文档、结构设计与代码仓库雏形。
- 支持 CLI 与库两种使用方式，强调从需求到产物链路。
- 围绕 Agent 工作流自动化持续演进并提供研究输出。

## 值得保留的方法或框架

- 角色化分工: 通过职责边界提升多代理协作稳定性。
- SOP 显式化: 将流程知识转成可执行规范。
- 从需求到仓库: 关注端到端产出而非单点工具调用。

## 局限与偏见

- 角色体系复杂，落地需要较强流程设计能力。
- 自动生成产物仍需工程审查与质量把关。
- 长链流程在成本与时延上要求更高。

## 可迁移知识

- 多代理系统可先从“角色职责”定义入手。
- SOP 文档化有助于将经验沉淀为可执行资产。
- 端到端自动化要配合分阶段验收策略。
