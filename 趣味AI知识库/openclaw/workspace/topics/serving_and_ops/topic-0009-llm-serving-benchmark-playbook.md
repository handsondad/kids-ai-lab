# 一句话定义

这是一张可直接执行的压测手册卡，目标是用统一请求集和统一指标体系，对比不同推理方案在质量、时延、吞吐和成本上的真实表现。

## 为什么重要

- 没有统一压测流程，工具选型会被单次体验或局部指标误导。
- 压测结果是团队决策和资源投入最关键的证据。
- 这张卡能把测试从临时脚本升级成可复用流程。

## 压测范围定义

- 对比对象：至少 2 套服务方案，例如 vLLM、SGLang、Xorbits Inference。
- 任务类型：覆盖你的真实任务组合，例如对话、摘要、结构化输出。
- 流量形态：覆盖低并发、稳态并发、突发并发三种负载。

## 指标清单（统一采样）

- 时延指标：P50、P95、P99。
- 吞吐指标：tokens/sec、requests/sec。
- 质量指标：任务成功率、格式正确率、关键字段准确率。
- 稳定性指标：错误率、超时率、重试率。
- 成本指标：每千 token 成本、单位成功请求成本。

## 执行步骤

1. 固化测试集：固定提示模板、输入样本、输出校验规则。
2. 固化环境：记录硬件、模型版本、服务参数和并发配置。
3. 运行三轮：每轮独立执行，避免单轮偶然性。
4. 汇总报告：按场景输出赢家，不做全局单一赢家。
5. 复验结论：对关键差异做一次复跑确认。

## 报告模板建议

- 场景 A（低并发）：推荐方案 + 原因 + 风险。
- 场景 B（稳态并发）：推荐方案 + 原因 + 风险。
- 场景 C（突发并发）：推荐方案 + 原因 + 风险。
- 统一结论：默认方案、备选方案、触发切换条件。

## 常见误区

- 只跑短样本，忽略长上下文负载。
- 只看平均值，不看尾延迟和失败模式。
- 测试环境不一致却直接横向比较。

## 下一步学习建议

- 在你当前集合中选择 2 到 3 个代表业务场景，先做最小压测版。
- 结合 topic-0010 的迁移策略，提前设计故障回滚演练。
